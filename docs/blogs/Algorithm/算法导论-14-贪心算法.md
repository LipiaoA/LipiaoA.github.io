#### 算法导论-14-贪心算法

贪心算法是这样一个算法，它在每一步都做出当时看起来是最佳的选择，也就是说，它总是做出局部最优的选择，寄希望于这样的选择能导致全局最优解。

#### 1.活动选择问题

**问题描述**

假定有一个 $$n$$ 个活动的集合 $$S = \{ a_1，a_2，\cdots，a_n\} $$ ，这些活动使用同一个资源（比如同一个教室），而这个资源在某个时刻只能供一个活动使用。每个活动 $$a_i$$ 都有一个开始时间 $$s_i$$ 和一个结束时间 $$f_i$$ ，其中 $$ 0 \geqslant s_i < f_i < \infty $$ 。如果任务被选中，任务 $$a_i$$ 将发生在半开区间 $$[s_i，f_i) $$ 期间。如果两个活动的活动时间不重叠，我们称这两个活动是兼容的。在该问题中，我们希望选出一个最大兼容的活动集合，假定给出数据已经按照活动结束时间进行排序。

我们通过动态规划的方法将这个问题划分为两个子问题，然后将两个子问题的最优解整合成原问题的一个最优解。在确定该将哪些子问题用于最优解时，要考虑几种选择。实际上贪心算法只需要考虑一个，在做贪心选择时，子问题之一必定是空的，因此只留下一个非空子问题。

**活动选择问题的最优子结构**

我们令 $$S_{ij}$$ 表示在 $$a_i$$ 结束之后开始，且在 $$a_j$$ 开始之前结束的那些活动的集合。假定我们希望求解 $$S_{ij}$$ 的一个最大互相兼容的活动子集，进一步假定 $$A_{ij}$$ 就是这样一个子集，包含活动 $$a_k$$ 。由于最优解包含 $$a_k$$ ，我们就可以得到两个子问题：寻找 $$S_{ik}$$ 中的兼容活动以及寻找 $$S_{kj}$$ 中的兼容活动。令 $$A_{ik} = A_{ij} \bigcap S_{ik} $$ 和 $$A_{kj} = A_{ij} \bigcap S_{kj} $$ ，这样 $$A_{ik} $$ 包含 $$A_{ij}$$ 中那些在 $$a_k$$ 之前开始的活动，$$A_{kj}$$ 包含了 $$A_{ij} $$ 中那些在 $$a_k$$ 结束之后开始的活动。因此，我们有 $$ A_{ij} = A_{ik} \bigcup A_{kj} \bigcup \; \{a_k\} $$ ，而且 $$S_{ij}$$ 中最大兼容任务子集包含 $$|A_{ij} | = |A_{ik}| +  |A_{kj}|  + 1 $$ 个活动。

我们依旧可以用反证法证明 $$A_{ij} $$ 包含了 $$S_{ik} $$ 和 $$S_{kj} $$ 两个任务子集的最优解。这样刻画子问题的最优子结构，我们可以使用动态规划的方法求解活动选择问题。定义 $$c[i，j] $$ 表示集合 $$S_{ij}$$ 的最优解大小，则可得递归式
$$
c[i,\;j] = 
\left\{ \begin{array}{ll}
0 & 若 \; S_{ij} = \emptyset \\
\max\limits_{a_k \in S_{ij}} \{c[i, \; k]，c[k, \; j] + 1\} & 若 \; S_{ij} \neq \emptyset
\end{array} \right.
$$
于是，后面可以实现一个带备忘的自顶向下递归算法，或者一个自底向上填写表项的算法来求解该问题。

**贪心选择**

如果我们不需要迭代所有子问题就能够选出一个活动加入到最优解，这将使我们可以省略掉上述递归式中考察所有的选择的过程，可以极大的节省时间。从直观上来看，我们应该选择这样一个活动，即该活动完成后，应该剩下尽可能多的资源供其它活动使用，这样能够达到选择的活动数量最大化问题。现在考虑可选的活动，其中必然有一个最先结束。直觉告诉我们，选择尽可能早结束的活动可以留下更多的资源能够尽量被其它活动使用。

因活动已按照结束时间排序，因此第一个活动我们选择 $$a_1$$ ，而后仅剩下一个子问题，在 $$a_1$$ 结束之后开始的活动中选择出一个活动。

与动态规划不同的是，贪心选择算法通常采用自顶向下的设计：做出一个选择，然后求解剩下的那个子问题，而不是自底向上的求解出很多子问题，然后再做选择。

```c++
int activite_select(vector<vector<int>> act) {
	int res = 1;
    int e_tim = act[0][1];				// 先选择出第一个活动，记录其结束时间
    int nu = act.size();				// 活动总数量
    for (int i = 1; i < nu; ++i) {		 // 迭代所有活动
        if (act[i][0] >= e_tim) {		 // 找一个在上一个活动结束之后开始的活动
            e_tim = act[i][1];
            ++res;
        }
    }
    return res;
}
```

上面实现，一个活动数组，内容分别是开始时间和结束时间，具体算法过程已在代码中标注，不再赘述。当然上述给出了迭代实现的版本，感兴趣可以自己写一版递归算法实现的版本。

#### 2.贪心算法原理

我们可以按照如下步骤设计贪心算法：

1. 将最优化问题转化为这样一种形式：对其做出一次选择后，只剩下一个子问题需要求解。
2. 证明做出贪心选择后，原问题总是存在最优解，即贪心选择总是安全的。
3. 证明做出贪心选择后，剩余的子问题满足性质：其最优解与贪心选择组合即可得到原问题的最优解，这样可以得到最优子结构。

贪心算法适用于哪些问题，这个并没有适合所有情况的方法。但贪心选择性质和最优子结构是两个关键要素。如果我们能够证明问题具有这些性质，就向贪心算法迈出了重要一步。

**贪心选择性质**

我们可以通过做出局部最优选择来构造全局最优解。换句话说，在我们进行选择时，我们直接做出在当前问题中看来最优的选择，而不是考虑子问题的解。与动态规划不同之处在于，它在每个步骤中进行选择时，都需要依赖于子问题的解，因此动态规划是自底向上解决问题。贪心选择时我们总是做出当时看起来最佳选择，然后求解唯一剩下的问题，这在进行选择时可能会依赖于之前做出的选择，但不依赖于将来的选择或是子问题的解。

我们需要证明每个步骤做出的贪心选择能生成全局最优解。这种证明通常首先考查某个子问题的最优解，然后用贪心选择替换某个其他选择来修改此解，从而得到一个相似但更小的子问题。

**最优子结构**

如果一个问题的最优解包含其子问题的最优解，则称此问题具有**最优子结构**性质。应用于贪心算法时，我们通常使用更为直接的最优子结构。我们可以假定，通过对原问题应用贪心选择即可得到子问题。真正需要做的全部工作就是论证：将子问题的最优解与贪心选择组合在一起就能生成原问题的最优解。这种方法隐含地对子问题使用了数学归纳法，证明了在每个步骤进行贪心选择会生成原问题的最优解。



**贪心&动态规划**

这两个算法策略都利用了最优子结构性质，你可能会对一个可用贪心算法求解的问题使用动态规划，或者相反。接下来通过讨论一个经典问题的两个变形来说明这两者之间的细微差别。

​	**0-1背包问题：**一个正在抢劫商店的小偷发现了 $$n$$ 个商品，第 $$i$$ 个商品价值 $$v_i$$ 美元，重 $$w_i$$ 磅，$$v_i$$ 和 $$w_i$$ 都是整数，他希望拿走价值尽量高得商品，但他的背包最多能容纳 $$W$$ 磅重的商品，$$W$$ 是一个整数。如何选择这些商品？（商品不可分割）

​	**分数背包问题：**问题设定与 0-1背包问题是一样的，但对每个商品，小偷可以拿走其一部分，而不是只能做出二元选择。

对于分数背包问题来讲，我们可以通过先计算每个物品单位重量的价值 $$ v_i / w_i $$ ，然后每次根据贪心选择单位价值最高的物品即可，直到装满背包。但对于0-1背包问题，我们不能这样做，简单来讲，就是因为商品不可再分，需要考虑背包最终可能余下的空间问题。

#### 3.赫夫曼编码

赫夫曼编码可以很有效的压缩数据：通常可以节省20%-90%的存储空间，具体压缩率依赖于数据的特性。我们将待压缩的数据看做字符序列，根据每个字符出现的频率，赫夫曼贪心算法构造出字符的最优二进制表示。

相较于对字符的定长编码而言，通常变长编码可以达到比定长编码好很多的数据压缩率，其思想是给高频的字符以短码字，而对低频的字符以长码字。

当前我们仅讨论前缀码，即没有任何码字是其它码字的前缀。由于没有任何码字是其它编码的前缀，可以很容易的解码出文件开始的码字，然后对剩下的码字做相同的操作。二叉树形式是前缀码解码过程识别码字时的一种方便表示形式，其叶节点是给定的字符，字符的二进制码字用从根节点到该字符叶节点的简单路径表示，其中0意味着“转向左子节点”，1代表“转向右子节点”，看下图：

![ScreenShot_2026-01-21_100518_607](D:/华为家庭存储/01-workspace/2-Docs/00-LeaRecord/ScreenShot_2026-01-21_100518_607.png)

如上图所示，从根节点到叶节点的简单路径上左右转的0，1组合起来就是对应叶节点字符的编码。解码过程相同，从根结点开始，根据编码选择左右子树路径，直到叶节点便解码完成一个字符。

文件的最优编码方案总是对应一个满二叉树，即每个非叶节点都有两个孩子节点。若 C 为字母表且所有字符出现的频率皆为正数，则最优前缀码对应的树恰好有 $$|C|$$ 个叶节点，每个叶节点对应字母表中的一个字符，且恰好有 $$|C| - 1 $$ 个内部结点。

给定一棵对应前缀码树 $$T$$ ，我们可以计算出编码一个文件需要多少个二进制位。对于字母表 $$C$$ 中的每个字符 $$c$$ ，令属性 $$c.freq$$ 表示 $$c$$ 在文件中出现的频率，令 $$d_T(c)$$ 表示 $$c$$ 的叶节点在树中的深度。注意，$$d_T(c) $$ 也是字符 $$c$$ 的码字长度。则编码文件需要
$$
B(T) = \sum_{c\in C}{c.freq \;\cdot\; d_T(c)}
$$
个二进制位，此处将 $$B(T)$$ 定义为 $$T$$ 的代价。

**构造赫夫曼编码**

赫夫曼设计了一个贪心算法来构造最优前缀码，被称为**赫夫曼编码**（Huffman code）。算法过程较为简单。首先，假定字符集合 $$C $$ 包含 $$n$$ 个字符。对集合中的每个字符 $$c \in C $$ ，将其视为一个对象，并用属性 $$ c.freq$$ 表示该字符出现的频率。将集合 $$C$$ 中的所有字符对象按照频率从小到大排序。每一步从中选取频率最小的两个节点，生成一个新的内部节点，并将这两个节点作为其左右子节点。新生成节点的频率等于两个子节点频率之和。随后，将该新节点重新插入到节点集合中，并保持按频率排序。重复上述过程，直到所有节点被合并为一个根节点为止。

```c++
HUFFMAN(C)
    n = |C|
    Q = C
    for i = 1 to n - 1
        allocate a new node z
        z.left = x = EXTRACT-MIN(Q)  // 取出最低频率的两个节点
        z.right = y = EXTRACT-MIN(Q)
        z.freq = x.freq + y.freq
        INSERT(Q, z) 				// 将新构造的节点插入到Q中
     return EXTRACT-MIN(Q)
```

假定 $$Q$$ 使用最小二叉堆结构，上述代码需要总运行时间为 $$O(\lg n)$$ 。

**赫夫曼算法正确性**

**引理**：令 $$C$$ 为一个字母表，其中每个字符 $$c \in C$$ 都有一个频率 $$c.freq$$ 。令 $$x$$ 和 $$y$$ 是 $$C$$ 中频率最低的两个字符。那么存在 $$C$$ 的一个最优前缀码，$$x$$ 和 $$y$$ 的码字长度相同，且只有最优一个二进制位不同。

此处记录一下证明思路，先假定 $$T$$ 是任意最优前缀编码对应的编码树，对该树进行修改，得到另一个表示最优的前缀编码树，使得在新树中，$$x$$ 和 $$y$$ 节点是深度最大的节点，且它们为兄弟节点。假定 $$a$$ 和 $$b$$ 节点是这棵树中深度最深的两个兄弟叶节点，通过两步，将 $$x$$ 和 $$y$$ 节点交换过来，中间生成 $$T'$$ 和 $$T''$$ 两棵树，通过计算其最终增加的代价为0，由此可以找到这棵最优前缀编码树。

下一步通过最优子结构的性质以反证法证明，通过每次合并最低两个频率的节点并插入新节点这种方式最终将得到的树一定是最优前缀编码树。结合上述说明，最终说明赫夫曼算法会生成一个最优前缀编码。

#### 4.拟阵和贪心算法

**拟阵**

一个拟阵是一个满足如下条件的序偶 $$M = (S，I) $$ :

1. S 是一个有限集。
2. $$I$$ 是 S 的子集的非空族，这些子集被称作 S 的独立子集，使得如果 $$B \in I$$ 且 $$ A \subseteq B $$，则 $$A \in I$$。如果 $$I$$ 满足此性质，则称之为**遗传的**。注意，空集 $$\emptyset $$ 必然是$$I$$ 的成员。
3. 若 $$A \in I$$ 、$$B \in I $$ 且 |A| < |B| ，那么存在某个元素 $$ x \in B - A $$，使得 $$A \bigcup \{x\} \in I$$ ，则称 M 满足交换性质。

上面的定义甚是抽象，在这用个例子解释下，给定一堆的向量，即此处的集合 S，从这一堆向量中选出尽可能多的向量，要求他们线性无关，不论如何选择，其最终能加多少个是固定的，可以得到一个**基**。在这件事儿中，有几个特性：

1. 一组线性无关的向量的任何子集，仍然线性无关
2. 可以不断扩展，即如果集合 $$A$$ 比 $$B$$ 小，那么总可以从 $$B$$ 中掏点儿东西给到 $$A$$ ，使得 $$A$$ 仍然合法
3. 贪心有效，即你可以随便选 “当前看起来可行” 的向量，不会后悔

拟阵是将这三件事儿从 “线性无关” 中抽象出来。讲人话，一个拟阵由两部分组成 $$M = (S，I)$$ ，$$S$$ 一个有限集合，在这就是上面给的一堆向量。而 $$I$$ 则是 $$S$$ 的一些合法（线性无关）子集，可以和这选出来的不同的线性无关集合对应。第一，空集 ∅ 在集合 $$I$$ 中，啥也不选总不会错。第二，遗传性指选出来的子集 $$A$$ 是合法的，那么从$$A$$ 中拆掉一部分，剩下的也是合法的（难道剩下的就线性相关了吗？显然不是）。第三，交换性是说如果 $$A，B$$ 都是合法集合，并且 |A| < |B| ，那么一定可以找到个元素 $$x \in B - A$$，放到 $$A$$ 中使得 $$A \bigcup \{x\} $$ 仍然合法，大概就这么回事儿。此处的交换性质直接保证了贪心算法在做出最优选择时，在最终能够达到整体最优的结果。

给定一个拟阵 $$M = (S，I) $$ ，如果对一个集合 $$A \in I $$ 和一个元素 $$x \notin A$$ ，将 $$x$$ 加入 $$A$$ 会保持独立性质，则称 $$x$$ 是 $$A$$ 的一个**扩展**。换句话说如果 $$A \bigcup \{x\} \in I $$ ，则 $$x$$ 是 $$A$$ 的一个扩展。

**加权拟阵上的贪心算法**

给定一个加权拟阵 $$M = (S，I) $$ ，我们希望寻找独立子集 $$A \in I$$ 使得 $$w(A)$$ 最大。我们称这种独立且具有最大可能权重的子集为拟阵的最优子集。由于任何元素 $$x \in S$$ 的权重 $$w(x)$$ 总是正的，则最优子集必然是最大独立子集，用**最小生成树问题**进行说明。

给定一个联通无向图 $$G = (V， E) $$ 和一个长度函数 $$w$$ ，使得 $$w(e) $$ 表示边 $$e$$ 的长度（正值）。我们希望找到一个边的子集，能链接所有顶点，且具有最小总长度。为了将此问题描述为寻找拟阵最优子集问题，我们考虑加权拟阵 $$M_G$$ ，其权重函数为 $$w'(e) = w_0 - w(e)$$ ，其中 $$w_0$$ 为一个大于最大长度边的值。可以确定的是，在此加权拟阵中，所有的权重均为正值。另外也比较容易能推导出，最大化的 $$w'(A) $$ 必然能得到最小化的 $$w(A)$$ 。因此，任何能求得任意拟阵中最优子集 $$A$$ 的算法，均可以求解最小时生成树问题。下面给出通用的加权拟阵算法：

```c++
GREEDY（M, w）
	A ≠ ∅
	sort M.S into monotonically order by weight w  
	for each s ∈ M.S，taken in monotonically decreasing order by weight w(x)
		if A ∪ {x} ∈ M.I	// 检查 x 加进去之后是否保持独立集的性质 否则不加
			A = A ∪ {x}
	return A
```

 简单说明，先将拟阵 $$M$$ 中元素 $$S$$ 按照权重 $$w$$ 由高到低排序，将 $$x$$ 加入之前先检查加入后是否能保持集合独立，最终我们可以得到最大权重子集 $$A$$ 。最后，拟阵是具有最优子结构的性质，令 $$M = (S，I) $$ 是一个拟阵，如果 $$x$$ 是 $$S$$ 中第一个被上述算法过程选出的元素，则接下来寻找一个包含 $$x$$ 的最大权重独立子集的问题归结为寻找加权拟阵 $$M' = (S'，I') $$ 的一个最大权重独立子集的问题，其中
$$
S' = \{ \; y \in S: \{x，y\} \in I \; \} \\
I' = \{ B \subseteq S - \{x\}: B \cup \{x\} \in I \}
$$
$$M'$$ 的权重函数就是 $$M$$ 的权重函数，但局限于 $$S'$$ 中的元素（我们称 $$M'$$ 为 $$M$$ 在元素 $$x$$ 上的收缩）。



#### 5.用拟阵求解任务调度问题

单位时间任务是严格需要一个时间单位来完成的作业。给定一个单位时间任务的有限集合 $$S$$ ，对 $$S$$ 的一个调度是指 $$S$$ 的一个排列，它指明了任务执行的顺序。第一个任务调度开始于 0 时刻，终止于时刻 1，第二个任务开始于时刻 1，终止于时刻2，依此类推。

单位处理器上带截止时间和惩罚的单位时间任务调度问题输入：

1. n 个单位时间任务集合 $$ S = \{ \;a_1，a_2，\cdots ，a_n \;\} $$ 。
2. n 个整数截止时间 $$d_1，d_2，\cdots，d_n$$ ，每个 $$d_i$$ 满足 $$1 \leqslant d_i \leqslant n $$ ，我们期望任务 $$a_i$$ 在时间 $$d_i$$ 之前完成。
3. n 个非负权重或惩罚 $$w_1，w_2，\cdots，w_n$$ ，若任务 $$a_i$$ 在时间 $$d_i$$ 之前没有完成，我们会受到 $$w_i$$ 这么多的惩罚，如果任务在截止时间前完成，则不会受到惩罚。

我们希望找到 $$S$$ 的一个调度方案，能够最小化超过截止时间导致的惩罚总和。

考虑一个给定的调度方案，如果方案中一个任务在截止时间后完成，我们称之为**延迟**的；否则，称之为**提前**的。对于任意调度方案，我们总是可以将其转换为**提前优先形式**，即将提前的任务都置于延迟的任务之前（这玩意不影响任务的延迟或者提前），而且我们可以将一个任意的调度方案做这样的转换（提前任务都在延迟任务之前，反正都惩罚都一样，延迟多少也就无所谓了）。然后，只要调度方案中存在两个提前任务 $$a_i$$ 和 $$a_j$$ ，分别在时刻 $$k$$ 和 $$k+1 $$ 时刻完成，使得 $$ d_j < d_i $$ ，我们就交换这两个任务的位置（交换后这两个任务仍旧是提前的），这么做的好处是因为 $$d_i > d_j $$ ，把任务 $$ a_j$$ 换大前面去之后，在 $$a_j$$ 和 $$ a_i$$ 之间就有机会可以插其它任务了。

这样，我们将找最优调度方案问题归结为寻找提前任务子集 $$A$$ 的问题。确定 $$A$$ 之后，我们可以将 $$A$$ 中元素按照截止时间递增的顺序排列，将延迟的任务放在放在后面即可。对于一个任务集合 $$A$$ ，如果存在一个调度方案，使 $$A$$ 中所有任务都不延迟，则称 A 是独立的。显然，一个调度方案的提前任务集合构成一个独立任务集。令 $$I$$ 表示所有独立任务集的集合。最后就是最小化延迟任务的惩罚之和问题与为最大化提前任务的惩罚之和是等价的。

对该问题的重点已经在上面描述完了，剩下的就是使用贪心算法，先寻找一个最大权重的独立任务子集 $$A$$ ，然后把剩下的任务任意添加在 $$A$$ 后面即可。具体定义拟阵 $$M = (S，I) $$ ，其中 $$S$$ 是给定了截止时间的单位时间任务集合，$$I$$ 是所有独立任务集合的集合，由此可以找到 $$A$$ 。
