Linux并发性能分析 - 记录

#### 写在前面

​	听同事描述，原以为会很麻烦，毕竟搞了挺久都没搞出来，还建议去看看系统L1 L2 L3缺失情况。

#### 概述

​	某一款软件A，工作中我们开发的一款模拟软件，一个较大的Patch合入后，CI发现当并发量上去之后，程序执行时间会迅速劣化，执行性能成倍下降，查看了IO情况，CPU占用情况，内存使用情况都没有啥问题。IO占用没满，并发数量小于CPU实际核数量，内存也未占满，但就是性能下降了。



#### 分析

​	最开始给出上述说明的时候，我已经猜到大概是系统缓存沾满了，访存miss率上升导致的。原因有几点，第一新合入的Patch里面不存在文件的读写情况。第二，单个程序本省性能下降幅度比较小，在可接受范围内，也就是说只有并发的情况下才会有这个问题。第三合入的Patch只会有内存占用增加情况，结合上述原因，我认为是访存中Cache缺失率上升导致的，最开始已给出建议，关注系统Cache缺失情况，无奈，技术不行。

​	今天问题不能说分析完了，但也大致确定了原因。单个程序跑的时候系统L3-Cache miss率在2.5%左右。但当并发数量上升到核数量减1的时候，L3-Cache miss 率急剧上升到40%，程序整体性能下降了2倍。

#### 小结

​	上述给出了猜测，并没有完整的完备的分析论证过程，在这只是记述一下这件事儿，并记录下Linux查看缓存缺失率的办法。

#### 命令

```sh
# -a: 统计系统所有进程
# -e：指定关注的事件
# sllep 10：让perf 采样10秒钟
sudo perf stat -a -e  L1-dcache-loads,L1-dcache-load-misses,LLC-loads,LLC-load-misses sleep 10
```
